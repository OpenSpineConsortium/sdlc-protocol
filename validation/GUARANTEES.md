# Guarantees

One row per guarantee of DESIGN.md section 2.3: the sentence of spec/PROTOCOL.md it restates, quoted word for word, and its status in the harness as it stands. tests/test_validation_guarantees.py holds this file to the spec and to validation/invariants.py: every quote must be in the spec as written, every guarantee the invariants name must have a row here and every row a guarantee, and a guarantee the invariants check may not be marked "not checked". So a spec edit that rewords one of these sentences fails that test until this file, and the oracle where it quotes the same words, follow.

The statuses:
- **checked**: an invariant checks it on every step it applies to, in the tests and in every search; no trace reached so far breaks it.
- **checked, under F8**: as checked, under the assumption the spec states, that idleness is the committer date the pusher sets (finding F8).
- **known (F...)**: checked, and the named open finding contradicts it: either the oracle reads that rule as the library is built (oracle.AS_BUILT) and without the switch the harness reports the finding, or, for F7, which no board rule answers, the finding shows only under the careless scope, whose verbs do what the rules forbid and git allows.
- **partly checked**: the part this step's worlds reach; the rest waits for the build step named.
- **not checked yet**: no world of this step reaches it; the build step named adds it.

As it stands is build step 4 of DESIGN.md section 14: the memory world, the fake GitHub, the board run, the verbs, the scripted workers, the oracle and the invariants (step 1), the mutation lane (step 2), the run in two halves with its concurrency group (step 3), and the fast lane (step 4): the scenarios S01 to S05 (validation/scenarios.py, run.py), the guard grammar judged by git's recorded answers (validation/guard_grammar.py, guard_git.json), dealing (validation/dealing.py, clerk.py), the property lane (validation/properties.py, domains.py) and the table tests (tests/test_validation_tables.py). "Checked" here means checked by the unit tests' traces, by the searches tests/test_validation_explore.py runs (two workers on one issue to depth 4) and by the fast lane's searches in tests/test_validation_fast_lane.py, all in the required check: two workers on one issue to depth 5 (29,531 states), three workers to depth 4, depth 3 from each scenario's prefix, and every fault kind from a due claim; none found a violation on the library as it stands. The mutation lane (validation/mutants.py) holds 25 mutants of the library's rules, each caught by a lane or a search from a short prefix, and each on its shortest trace in the required check. The deep lane (two issues at depth 7, one at depth 8, the git world, BareGitWorld) is build step 6.
