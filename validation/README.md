# Validation

This folder is for checking that the library keeps the promises spec/PROTOCOL.md makes, by running the library's own code, not a copy of it, against scripted workers, a fake of GitHub that keeps state, and real git, and judging every step by an oracle written from the spec's own text. It lives beside the package and never inside it: scripts/vendor.py copies only `sdlc_protocol/`, so nothing here reaches a consumer, and a commit that changes only this folder brings no sync pull request, since a copy's record names the last commit that changed the package.

[DESIGN.md](DESIGN.md) is the design of the harness, with the findings F1 to F12 its prototype and its critique turned up and the status of each, and the order the harness is built in (its section 14). [prototype/](prototype/) is the prototype that design measured, kept so every number in DESIGN.md can be reproduced; [prototype/README.md](prototype/README.md) says how to run each script and what it printed.

## What is built: step 1, the foundations in memory

- model.py: what GitHub and git hold for one repository (commits, refs, issues with their labels, label events and comments, pull requests, who may write), on a clock only the scenario moves. A push follows git's rules: the first push of a name creates it, a second is refused unless it fast-forwards, and a lease is refused when the pusher's view of the remote is stale. The state key, `canonical()`, is everything a guarantee, the oracle or a scripted worker reads, the board's last page included, with nothing reduced.
- fake_github.py: an opener the library's own adapter runs against, answering from the model and changing it on writes. It encodes the request line as ASCII as http.client does, serves pages of 100 with a Link header, answers `mergeable` null on the first read, and takes faults by method and path (a 500, a 403, a 422, a secondary rate limit, a write GitHub makes and loses the answer to). An endpoint it does not model raises, so the harness never mistakes a gap in the fake for a failed run.
- cycle.py: one board run in cli.board_live_run's order on the model's clock; the board branch is written only when the run exits 0. tests/test_validation_cycle.py pins that order to cli.py's.
- verbs.py: the atomic verbs of workers, people, the owner, the clock and the board, every push passed through the push guard first, as the template's hook does; a careless scope adds the verbs the rules forbid but git allows.
- oracle.py: the spec's terms over the model, spelled and quoted as the spec writes them and importing nothing from the package; from the state before a run it computes what the run must do. `AS_BUILT` holds the findings still open on the library (F2, F9, F12, and F13 and F14, which this step found): with a switch on, the oracle reads the rule as built; with it off, the finding shows.
- invariants.py: the guarantees G1 to G15, checked on every state, every command and every board run: the run's effects must equal the oracle's, each release in the spec's order, a rename GitHub refused for good is said once, a run never fails over a refused write or a branch name (G15), and a second run with nothing new writes nothing. Whether a run was touched by an injected fault is read from its calls, so a fault that never fires leaves every check on.
- explore.py: breadth-first search over every interleaving of the verbs a scope enables, keyed by the full state, going on past a violation, so the first trace that breaks a guarantee is a shortest one.
- policies.py: scripted workers that act on the page alone (an eager claimer, an idle holder, an abandoner, a finisher, a person releasing by hand, a stranger).
- page.py: reads STATE.md's sections back for the policies and the checks.
- [GUARANTEES.md](GUARANTEES.md): one row per guarantee, with the spec's sentence and its status.

The tests are tests/test_validation_*.py, part of `python3 -m unittest discover -s tests` and so of the required check: 84 tests in about 5 seconds. They search every interleaving of two workers' verbs on one issue to depth 4 (about 3,000 states) with no violation on 0.4.1, show each open finding with its switch off, show F7 under careless workers, catch every mutant of the lane on its shortest trace, and hold the oracle and GUARANTEES.md to the spec's text word for word.

Holding the oracle to the spec's words found two readings where the library and the spec part, recorded as F13 and F14 in DESIGN.md's section 13 for the owner to settle: the Overlaps' landing order reads "the oldest" as the lowest number, an issue's and a pull request's alike, and Given to workers needs the label todo, which the spec's sentence does not ask for.

## What is built: step 2, the mutation lane

- mutants.py: 19 mutants, each one rule of the library changed inside the process by patching one attribute, never in the files, with the guarantee it should break; and four breadth-first searches, each from a short prefix with no board run in it (a released claim under every fault, careless workers on a held claim, two claims on one file, a held claim with the clock and a release by hand), cheapest first. A mutant is caught when a search meets a violation under it that the library itself does not meet there; the careless search meets F7 on the library and says so. `python3 -m validation.mutants` runs the lane and prints, for each mutant, the search that caught it, the violation and its trace, and exits 1 when one slips or a search is red on the library beyond what it knows.
- The mutants: the seven step 1 caught on traces (idle at exactly 24 hours, a 12-hour idle time, the worker label left on, a release comment from any author, an idle comment to a released claim's pull request, the comment before the labels, a refused rename never said), and twelve more: a release that ignores the label claimed, a finished draft released by the coordinator, any comment read as a release, a board comment posted again, "main moved" told after any event, the rename skipped, overlaps told on every run, the labels not put back after a refused comment, a lost comment's release not seen, a writer's release not vouched for by the permission API, a claim number read with leading zeros (F5), and the guard passing a misnamed claim. All 19 are caught, the whole lane in about 90 seconds on one core.
- What the lane made the harness add, each a hole a mutant slipped through on the first run: G3L now fails a run whose release comment was written, its answer lost or not, and whose labels were put back, since the comment makes the release whole; G11a now fails a push the guard passed whose shape the rules forbid, not only an allowed one it refused; and the careless scope adds the owner's push of a misnamed claim by hand, which meets no guard, so a reader that takes `claude/01` for #1 is seen. The deeper searches also showed the oracle owing a "rename refused" comment for a branch pushed again at the head a release kept, which the board rightly deletes after GitHub's 422 (spec, Release: "A branch pushed again at the head a release already kept is deleted instead"); the oracle no longer counts that rename as refused for good. The library was not changed, and no mutant needed validation/equivalent.json.
- Not in the lane yet, since no world of the harness reaches them before step 4: the clerk dealing without its taken set, the guard accepting `--force` (no verb runs a forced push), and an overlap marker read from any line or by any author (no verb writes one).
- tests/test_validation_mutants.py, in the required check: the lane holds 10 to 20 mutants, each names a rule the library still has, and each is caught on the shortest trace the lane found, which the library itself passes. .github/workflows/validate.yml runs the lane itself on every pull request that changes the harness or the library, weekly, and by hand; it is not a required check.

The next step is the run as the workflow makes it (DESIGN.md, section 14, step 3): the concurrency group, with its pending run replaced, and the board run in two halves in cli.py.
